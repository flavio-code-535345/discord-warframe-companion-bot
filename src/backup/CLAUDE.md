# Server backups

Notes for this folder. The rules that apply everywhere, the commands and the list of the other notes are in the root `CLAUDE.md`.

**Backups** (`src/backup/`): `snapshot.ts` serializes the guild (bitfields as decimal strings; icon and emojis as base64 so they outlive the CDN; messages only with the Message Content intent) into `backups.data`. A small `summary` JSON sits next to it so listings stay cheap. `service.ts` holds `takeBackup` (single-flight) and `backupIfDue` (the hourly `backups` job: one a day, keeps 14 automatic backups). `restore.ts`: `planRestore` is pure and powers the confirmation preview. `restoreBackup` maps backup IDs to live or recreated IDs (roles first, then categories, then channels, then one bulk `setPositions`). It never deletes, it downgrades Community-only channel types, and it re-points Ordis's settings. The `/backup load` confirmation always takes a safety backup first. `test/backup.test.ts` drives the restore against an in-memory fake Guild.

**Database copies** (`database.ts`, the hourly `db-copy` job, `test/db-copy.test.ts`): the server backups above live inside `bot.db`, so the database itself is copied too. `databaseCopyIfDue` makes one copy a night (a night starts at 03:00 UTC; the first check after that makes it, and with no copy at all it is made at once): `Store.copyTo` (SQLite's online backup, `node:sqlite`'s `backup()`, a few pages at a time while the bot keeps working) writes a raw copy, a worker thread (`SCRUB`: plain JavaScript in a string, so it runs the same under tsx, in the tests and from `dist/`) empties `api_cache` and `panel_sessions`, removes bot_meta `panel_session_secret`, runs `VACUUM` (what was deleted is then really out of the file) and `PRAGMA quick_check`, and the result is gzipped to `<DATA_DIR>/backups/ordis-db-<date>-<time>-<auto|manual>.db.gz`. A file only gets that name once it is finished (`.tmp` and `.partial` before, cleared at the next run), calls that overlap share one copy, and the newest 7 nightly and 3 manual copies are kept. `listDatabaseCopies` reads the kind and the time from the name and lists only names that are exactly what `copyDatabase` writes, which is what makes it safe to look a name from an address up in it. A failed nightly copy is thrown on (the job's health shows it) and told to the staff once a night (`staffNotice`, bot_meta `db_copy_failed`). The panel's Backups page lists the copies, has "Copy now" and a download for owners (`src/web/CLAUDE.md`); `get_bot_health.databaseCopies` counts them. Restoring is by hand (README: gunzip over `bot.db` with the bot stopped); `wiki.db` is not copied, it can be crawled again. No environment variable.

# Screenshot roles

Notes for this folder. The rules that apply everywhere, the commands and the list of the other notes are in the root `CLAUDE.md`.

**Screenshot roles** (`src/ssroles/`, `/setup ssroles`): members post their in-game Profile screenshot in a dedicated channel and Ordis gives them roles. **The readers run in this order: 1. OCR, 2. the self-hosted Gemma on Ollama, 3. Gemini; images are never stored:** everything runs in memory, the member's message stays while Ordis replies to it and is deleted together with the reply `ssTimings.resultTtlMs` (a minute) after the result is shown, and the DB keeps only a sha256 and the in-game name (`ss_claims`, so a card can't be shared between accounts) plus a 256-byte grayscale fingerprint of the clan emblem and the clan's `Name#043` line (`ss_reference`, learned from `/setup ssroles reference:` and optionally `reference2:`: each picture is recognized by what it shows, a profile card teaches the emblem (two cards are stored back to back and the best match counts) and a clan roster row is only checked). `ocr.ts` is tesseract.js (WebAssembly, so no native dependency in the amd64-to-arm64 image; the English data comes from the `@tesseract.js-data/eng` npm package, `cacheMethod: 'none'`, one lazily created worker released after 5 idle minutes). `parse.ts` turns OCR lines into a `CardReading` (pure, tested on real OCR output; the rank is checked against the mastery-point curve, MR n needs 2500n² points and Legendary n needs 2,250,000 + 147,500n, and a title that disagrees counts as unreadable). `emblem.ts` decodes PNG/JPEG with pngjs/jpeg-js, finds the emblem as the picture above the clan name line (band scaled by the line height, found by difference from the panel colour) and compares fingerprints by Pearson correlation (`MATCH_THRESHOLD`). When OCR can't produce a complete card, the image is not PNG/JPEG, or the emblem can't be located, `vision.ts` (`readProfileCardVia`) asks the self-hosted `LOCAL_AI_*` model (Gemma on Ollama; thinking off, 120 s+ timeout; no limit, but 25-50 s per image on a CPU, and in early tests it flagged untouched cards as edited and missed roster rows) and, when that is missing, switched off, paused after failing (`localAvailable()`) or unable to read the image, the free-tier cloud model (the `FREE_AI_*` endpoint, daily allowance `allow()`); that path compares the clan text but not the emblem, and the mod log names the reader (`readerLabel`). `readLocal`/`readCloud`/`readWithOcr` (service.ts) each run one method, which the panel's **Screenshots** page (`src/web/admin/sstest-page.ts` + `sstest-client.ts`, `/admin/sstest`) uses: upload a picture (raw body, CSRF in the `X-CSRF-Token` header, streamed back as NDJSON with pings because a CPU model can take minutes) and run OCR, Gemma and Gemini separately or in order, seeing the reading, timing, recognised text and what `checkClan` would decide; the test ignores the Local switch and pause, does not count against the cloud allowance, stores nothing and changes no roles. `roles.ts` is pure: `checkClan` (name must equal `CLAN_NAME`; with a reference, `Name#tag` must match and the emblem must not differ), `masteryRank` (Legendary N = MR 30+N) and `planRoles`, which only uses roles that already exist and match by normalized name (`MR 33`, `Legendary 3`, `Clan`, the clan name, accolade titles); managed roles, roles above Ordis and roles with moderator permissions are skipped, and leadership, moderation and admin roles are **never** handed out by name (`isStaffRoleName`: Leadership, Founding Warlord, Rat Emperor/King/Lord/Count/Baron, Enhanced Permissions, anything with admin, moderator, staff or owner, the bot roles), so an edited picture naming one gets nothing, and mastery roles are one-at-a-time (older ones are removed). Roles are only given when the clan check passes. **Clan rank:** a second kind of screenshot, the row of the in-game clan member list (name and rank title such as `Rat Squire`), is recognized when OCR finds no profile card (`parseRankRow`, tolerant of one wrong letter); A message may carry both pictures (up to two are read; `handleSsMessage` reads all of them first, then handles profile cards before rows so the row's name can be one the card just verified, and answers once with one embed per picture; `test/ssroles-both.test.ts` drives it with a stub message). `handleRankRow` gives only the ranks in `SELF_SERVE_RANKS` (Rat Squire, Rat Knight; Baron and above are leadership-only, withheld because Baron needs 1000 hours a picture can't show), requires the row's name to be one the member verified with a profile card (`ownsName` against their `ign` claims, so a borrowed row is refused), and for Rat Knight an `MR 16+` role (`RANK_MIN_MASTERY`). The sticky shows two example pictures (`stickyImages`: up to two space-separated links, served as `/ss-example.png` and `/ss-example-rank.png`). The handler runs after the honeypot and before chat in `bot.ts`, does not need Message Content (with the intent off the gateway delivers messages with no attachments, which would make every screenshot look like chatter to remove, so a message without any is first re-read over REST with `message.fetch()`, and left alone if that fails), goes by the file header and not Discord's content type (`normalizeImage`, `src/imaging/sniff.ts`: a pasted PNG arrives labelled image/webp, which made OCR skip it and sent it to Gemma, which misread the clan as "The Rats Den#69"; a real WebP is converted to PNG), and logs to the mod log.

**Local model (Ollama)** (`src/ssroles/vision.ts`): `LOCAL_AI_URL` + `LOCAL_AI_MODEL` (+ optional `LOCAL_AI_KEY`, `LOCAL_AI_TIMEOUT_SECONDS` default 60) point at a self-hosted OpenAI-compatible server (Ollama `/v1`, reached over Tailscale or a tunnel). It is used only by the screenshot roles' vision fallback (before the free cloud `FREE_AI_*` model); a failure or timeout skips it for `LOCAL_COOLDOWN_MS` (3 min, `localAvailable()`) so a sleeping host doesn't slow every screenshot. The model is a plain setting (Config page or environment). `docker-compose.ollama.yml` is a separate stack for the machine with the RAM (tailscale sidecar, ollama with one parallel slot, 4096 context, flash attention and an 8-bit KV cache, a one-shot `pull-model`, and a one-shot `tune-model` that creates `ordis-tuned` with `num_thread` (6 for the i9-13900HK performance cores, `OLLAMA_THREADS`) and `num_ctx`); the bot reaches it over the tailnet. Removed on 2026-11-08 at the owner's request (everything that had been switched off or was only there to manage the model): the `/ai` command, the panel's AI page, the AI switches (`ai_toggle_*`), the `/ai model` choice (migration 35 moved it into the Config page's `LOCAL_AI_MODEL`), the `ollama_*`, `set_ai_switch` and `choose_ai_model` MCP tools, captcha verification and the live code patches (`ALLOW_CODE_EDIT`, the overlay). New vars follow the usual rule: config.ts, .env.example, compose, Portainer YAML.

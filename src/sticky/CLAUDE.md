# Sticky messages

Notes for this folder. The rules that apply everywhere, the commands and the list of the other notes are in the root `CLAUDE.md`.

**Sticky messages** (`src/sticky/service.ts`, `src/discord/commands/sticky.ts`, `/sticky set|edit|remove|list`, needs Manage Messages): not Discord pins. `set` and `edit` open a modal (heading, multi-line message, optional picture link; `edit` is prefilled), routed by the `sticky:save:<channelId>:<clean|keep>` custom ID in `bot.ts`; both run `checkStickyChannel` before the form and `saveSticky` after it. `StickyKeeper.onMessage` runs for every guild message (a cheap `stickies` lookup): after a 3 s debounce, capped by a 15 s max-wait so constant chat can't starve it, it posts a fresh copy of the sticky embed and then deletes the old one, so Ordis is the last speaker. Its own post is ignored (stored message id, plus a `busy` flag while reposting), `lastMessageId` skips a repost when the sticky is already last, and `saveSticky` forces one. Mentions are suppressed. **Clean mode** (`deleteOthers`) deletes everything other members post on arrival (staff with Manage Messages exempt), so the sticky is the only message and never needs reposting; it is refused in the chat, screenshot and riven channels, where Ordis has to read the message first. The screenshot channel's instructions are its sticky (`setupSsRoles` calls `saveSticky`), and its handler deletes non-screenshots itself. `StickyKeeper.onMessage` ignores that channel (`ssRolesChannelId`), so the instructions are never deleted and reposted: screenshots and replies remove themselves, so the sticky stays put.

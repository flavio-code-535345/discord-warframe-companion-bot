# Chat answers

Notes for this folder. The rules that apply everywhere, the commands and the list of the other notes are in the root `CLAUDE.md`.

**Chat answers** (`src/answers/`, no model anywhere; the owner decided on 2026-10-31 that a small CPU model was not reliable enough and asked to keep answers locked to the wiki): `smartAnswer(question, ctx)` in `smart.ts` answers in this order: thanks (a fixed line); nothing to look up (a link, emoji, `lol`: `silent`, the chat channel does not reply); a sum (`mathExpression` in `understand.ts` → `calculate` in `calc.ts`, a parser, never eval; besides plain arithmetic it takes the calculator's own functions and constants and the usual ways to write them: `sqrt(16)`, `max(2, 9)`, `2 * pi`, `√16`, "the square root of 16", "5 squared", "15% of 200", and a multiplication written without a sign, `2pi` or `3(4+1)`; `mathExpression` lets a message through only when it is made of nothing but those and has something to work out, so "what is e", "2026" or "100 (200)" is not a sum); the Circuit rotation (`circuit.ts`: the Steel Path Incarnon and normal Circuit Warframe tables parsed from the wiki's "The Circuit" page in the local index, this week's offer from `duviriCycle.choices`, counted to the Monday 00:00 UTC reset; "full schedule" lists every week with its start date); mastery rank thresholds (`mastery.ts`, from `pointsForRank` in ssroles/parse.ts); secondary element recipes (`elementsAnswer`, read from each element's wiki page); then the exact lookups by `detectIntent()` (`intent.ts`, pure regex rules: help, price, relic, world view, fissures, bounties, clan events, drops (the drop tables of the item and its blueprints, `relevantDrops`, never items that merely contain the word), an item card for a bare item name or a stats question, build (the item card)). Rule order matters: price before relic, and drops before world views; `test/intent.test.ts` pins real phrasings. Chatter that is not a question and names no wiki page is `silent`. **Everything else is `wikiAnswer`:** `searchWiki` on the local index, then one line of links (`📖 [Title](<url>)`, angle brackets so Discord shows no previews) to the 1-3 most relevant pages, and when the question names a page (`WikiIndex.subjectOf`), above it the one sentence of that page that fits the question best (`answerFrom(q, results, 400, 1)`), quoted word for word; a page that merely shares a word with the question is linked but never quoted. Nothing found gives a wiki search link (`found: false`). `test/answers.test.ts`. In the `/setup chat` channel Ordis answers anything written there (`chat.ts`): he skips messages with no text, a reply to another member's message, and `silent` answers. `src/discord/chat-topic.ts` keeps the channel's description (`CHAT_TOPIC`) in line with this: `syncChatTopic` runs at ClientReady and after `/setup chat`, the panel's Settings page and `update_bot_settings`, writes only when the topic differs and only with `ENABLE_MESSAGE_CONTENT` on, and needs Manage Channels (a failure just logs). It never undoes a hand edit: it replaces only an empty description or the text it wrote last time (`bot_meta` `chat_topic_written:<channelId>`), so a new `CHAT_TOPIC` arrives on its own but a description staff changed in Discord stays. Removed with the model answers (do not bring back without asking): the facts pipeline (a local Gemma wording gathered facts, grounding and sanity checks), the tool-using agent and its Brain page, operator mode, conversation memory, the thinking notice, the questions queue, embedding reranking of wiki results, the optional Claude chat, and (later the same day) staff corrections with their approval queue and Corrections page, the ✅/❌ answer ratings, the review list and `OPERATOR_IDS` (migration 29 drops the `corrections` table and the `ai_log` rating, review and message id columns).

**Question log** (`src/answers/log.ts`, `/ailog`, table `ai_log`): every answer given in the chat channel, in DMs or by `/ask` is recorded with asker, channel, question, intent, source (`excerpt` a quoted wiki sentence, `lookup`; older rows may say `local`, `cloud` or `correction`, sources that were removed), milliseconds and the start of the answer, and pruned after 30 days. `smartAnswer` fills `source/intent/ms`; `logAnswer` never throws. `/ailog [count] [member]` (Manage Messages) shows the newest entries plus the last 24 h per source.

# MCP server

Notes for this folder. The rules that apply everywhere, the commands and the list of the other notes are in the root `CLAUDE.md`.

**The server** (`server.ts`, mounted by `src/http.ts` at `POST /mcp` only when `MCP_AUTH_TOKEN` is set): stateless Streamable HTTP, a new `McpServer` and transport per request, so `createMcpServer` must not do I/O. A tool throws `UserError` for an expected failure, which comes back as an `isError` result; the tools call the same service layer as the slash commands (`src/services/clan.ts`), so behaviour stays the same. The world state tools return plain JSON built by `worldstate-summary.ts`: no Discord markup, ISO times plus an "in 2h 5m" string. The destructive tools need `confirm: true`.

**Insight MCP tools** (`src/mcp/insights.ts`): `test_answer` (runs a question through the chat path on the live bot without posting or logging), `get_ai_log` (questions, answers, source, with counts by source/intent, unanswered and repeated questions), `get_bot_health` (uptime, Discord, lifecycle, Warframe API pacing, the screenshot models and whether the local one is being skipped, wiki index, the relic book (`relicBook`), how much of Baro's visit is priced (`baroPrices`), the number of AlecaFrame links, answers in 24 h, which features are on), `list_member_levels` and `set_member_level` (lifts members to a level with `only_raise`, updates their Level roles; max 50 per call). `update_bot_settings` also takes `audit_log_channel_id`, `status_channel_id` and `level_channel_id`.

**Server admin over MCP** (`src/mcp/admin.ts`): `get_server_structure` plus create/edit/reorder/permission/archive tools for restructuring the clan Discord (`edit_server` also sets the verification level). Channels are never deleted: `archive_channel` moves one into a hidden "🗄️ ARCHIVE" category (found case-insensitively, so the old "Archive" spelling still counts) and returns its old state. The destructive tools are `delete_message` (one of Ordis's own messages, `deleteOwnMessage`, needs `confirm: true`), `clear_messages` (needs `confirm: true`; pair it with `read_messages` first, which also shows what a Components V2 message such as a board says: `componentText` in feeds/parts.ts) and `delete_role` (needs `confirm: true`; refuses @everyone, managed roles, roles at or above Ordis and roles still in the self-assign menu). `test_welcome` posts the join greeting (`postWelcome` in `src/discord/welcome.ts`, which links the rules and welcome guide found by name, the screenshot-roles and Ordis channels) for an existing member, to see it without someone joining. Positions are indexes within the parent category, because discord.js re-sorts siblings. Overwrites at creation need an explicit `OverwriteType`, since a member ID that isn't cached can't be inferred.

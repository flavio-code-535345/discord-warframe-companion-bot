# Squads and voice rooms

Notes for this folder. The rules that apply everywhere, the commands and the list of the other notes are in the root `CLAUDE.md`.

**Squad voice and activities** (`src/lfg/`): with `/setup lfgvoice`, `/lfg` creates a voice channel per squad (`voice.ts`). `lifecycle.ts` holds the pure rules (`sweepAction`: expiry, host-absent grace period, delete a closed squad's channel once empty), so they're testable without Discord. The once-a-minute `squad-voice` job (`sweepVoice`) applies them, which survives restarts and needs no per-channel timers; it reads who is in a channel from the cache, so the (unprivileged) GuildVoiceStates intent is required. `hostAbsentSince` starts at creation, so a host who never joins voice still ends the squad. The `activities` table (case-insensitive name, image URL, fixed channel; its ping role went with migration 38) feeds `renderLfg` (thumbnail) and the channel a squad is posted in; activities without a row still work. `squads.ts` `createSquad` is the one way a squad gets posted (`/lfg` calls it): in the activity's own channel, else where it was asked for, else in `lfgChannelId` (`/setup lfg`, MCP `update_bot_settings lfg_channel_id`); it creates the voice channel when squad voice is set up (one open voice squad per host), stores and posts the squad with its Join/Leave/Close buttons, and DMs the members with a `squad` tracker (`notifySquad`, never the host). Nobody is pinged in the channel; a post that fails closes the squad and removes its voice channel again. `autovc.ts` is join-to-create (`/setup autovc`): `handleVoiceStateUpdate` (a `VoiceStateUpdate` listener) makes a room per member in the lobby's category and deletes it when empty; rooms are tracked in `temp_voice` and `sweepTempVoice` (same minute timer) removes empty or vanished ones, sparing rooms younger than 30s so the owner can be moved in. `/vc` is owner-only and checks `temp_voice`. Image URLs must pass `validImageUrl` (plain https), which is why the admin panel's CSP allows `img-src https:`.

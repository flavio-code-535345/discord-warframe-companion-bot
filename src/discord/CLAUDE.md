# Discord layer

Notes for this folder. The rules that apply everywhere, the commands and the list of the other notes are in the root `CLAUDE.md`.

**Discord interactions** (`src/discord/bot.ts`): routes slash commands (`src/discord/commands/*`, each exporting a `Command`), autocomplete, and buttons (`src/discord/buttons.ts`). Commands are registered **guild-scoped** to `DISCORD_GUILD_ID` on every `ClientReady`; the bot deliberately serves only that one guild. Button custom IDs are `rsvp:<eventId>:<going|maybe|declined>`, `lfg:<postId>:<join|leave|close>`, `roles:<roleId>`, `giveaway:<id>:enter`, `notify:<weekly|clanEvent|squad>` (posts from before the rename carry `weekly:toggle`, routed to the same handler) and `feeds:<mine|plan|squad|incarnon>`, and the World State boards' menus are `feeds:track:<feed>`, `feeds:untrack`, `feeds:plan` and `feeds:bounty` (`handleFeedSelect`), so they keep working after restarts. The `/track pick what:` dropdowns (and `/track incarnon` without a weapon) answer with menus `trackpick:<incarnon|squads|sortie|arbitration>:<menu number>` (`handlePickSelect`, `src/discord/track-pick.ts`): the picked value is the choice, `*` means every squad, sortie or Arbitration, and a list over 25 choices is split over up to 5 menus. The wishlist card's menu is `wish:have:<wishId>` (`handleWishSelect`, `src/wishlist/`).

**Commands in a DM with Ordis** (`dm-commands.ts`, `test/dm-commands.test.ts`): `DM_COMMAND_NAMES` are the personal commands (`/now`, `/wf`, `/item`, `/price`, `/relics`, `/wishlist`, `/riven`, `/alecaframe`, `/drops`, `/wiki`, `/ask`, `/track`, `/clan`, `/remindme`); everything that posts in or changes the server stays in the server. They are also registered as **global** commands for the bot DM only (`contexts: [BotDM]`, so the server never lists them twice; `syncDmCommands` runs at ClientReady and only sends a changed list, kept in bot_meta `dm_commands`, because bulk overwrites are rate-limited; a new one may take up to an hour to show). The interaction guard in `bot.ts` lets a DM through only for these commands and the menus their replies carry (`DM_COMPONENT_PREFIXES`: `trackpick:`, `wish:`), and only when `isClanMember` finds the person in the server (a `guild.members.fetch`; "Unknown Member" 10007 is the only "no", cached a minute, a yes five; another failure is no answer and is not cached). Anyone else is told the bot serves the server. A command that reads `interaction.guild` or the channel must cope with a DM: the data modules use `ctx.config.DISCORD_GUILD_ID`, and `/remindme` stores no fallback channel when set in a DM. A new command that is safe in a DM gets its name in `DM_COMMAND_NAMES`.

**A command answered with one card** (`card-reply.ts`, `test/card-reply.test.ts`): `replyCard(interaction, building, { ephemeral })` replies with the Components V2 card itself when it is ready within 1.5 s, and otherwise defers first and edits the card in (deferring takes no V2 flag, the edit does). A failure while building is thrown on, so `replyError` answers it: privately as the reply when nothing was sent yet, as a follow-up after a deferral. `/now` and `/wishlist` use it.

**Notifier** (`src/discord/notifier.ts`, the `world-state` and `events` jobs): every minute `worldStateJob` reads the world state (fetched at most every `WORLDSTATE_POLL_SECONDS`) and the Arbitration schedule (`loadArbitrations`), builds one `FeedInput` (`feedInput`) and hands it to `syncFeeds` (the World State boards, `feeds/CLAUDE.md`), then DMs what matches the members' trackers, tells the members whose wishlist Varzia sells from (`notifyWishlistVarzia`, `src/wishlist/`) and the ones with relics worth cracking (`notifyCrack`, below; a failure of either is logged and stops nothing) and makes the weekly reset post. The Arbitration board and the Arbitration DMs work from the schedule alone, so they keep going while the world state is off or failing; a failed world state read is rethrown at the end, so the job's health shows it. The `events` job sends event reminders 15 minutes before start and re-renders ended events.

**`/now`** (`now.ts`, `commands/now.ts`, `test/now.test.ts`): one Components V2 card with what is worth doing at this moment, drawn from the same `FeedInput` as the boards (`nowInput` reads the two cached sources like the `world-state` job, so the command asks nothing new): the Arbitration with its tier (and the next A tier hour when this one is weaker), `quickFissures` (`src/warframe/fissures.ts`: per relic tier and kind the quick mission, `FAST`, that stays open longest; no storms, nothing that closes within 5 minutes, at most 8), the alerts and invasions whose reward passes `isNotableReward` (at most 5, the rest counted), night on the Plains and warmth in the Vallis, Baro (here with his best resale once priced, or arriving within 48 h), Darvo, running events, and the sortie and Archon Hunt resets in the last lines. `nowCard` is pure; its last lines (resets, the notes that data is missing or old, "As of") are taken out of the text budget first, so a busy day cuts the middle of the card, never its end. The row under it has the Arbitration board's "Squad up" button (when squads have a channel and an Arbitration runs) and link buttons to the boards that have a channel. `opts.personal` are lines only the member who asked may see: `commands/now.ts` passes `personalLines` (crack.ts: their relics worth cracking in the quick fissures, waited for at most 1.1 s) and passes none for a shared card. Only the member sees the card unless `share:True`. The answer goes through `replyCard`: both sources are cached, so the card is nearly always the reply itself.

**Crack now** (`crack.ts`, the pure reckoning in `src/alecaframe/crack.ts`, `test/crack.test.ts`): tracker kind `crack` (`/track crack [worth] [quiet]`, or "Crack now: my own relics" in the fissure board's menu; one per member, setting it again changes it; `crackLinkProblem` refuses it without an AlecaFrame link that shares relics). `notifyCrack` (every `world-state` round) DMs a member when a quick normal fissure with at least 20 minutes left is open for relics of theirs expected to pay `minPlat` or more a run (`crackDm`: per tier the worth, the fissure, the three best relics). Some quick fissure is open most of the day, so the member's quiet time paces it: at most one DM every `quietHours` (3 to 48, default 12). bot_meta `crack_state` keeps per tracker when it last spoke and when it looks next (`crackState`, `get_bot_health.crackNow`; the marks of removed trackers go with them): nothing is read from AlecaFrame while no such fissure is open or the member is in their quiet time, a look that found nothing to say (no relics worth it, no link, AlecaFrame not answering) is repeated half an hour later, and a member with closed DMs is tried again only after their quiet time.

**Identity:** `src/discord/identity.ts` syncs the bot's Discord username (`BOT_NAME`) and avatar (`assets/clan-logo.png`, which the Dockerfile copies into the image) on every `ClientReady`. It only calls the API when something differs, because Discord rate-limits both; the avatar hash is kept in the `bot_meta` table. Embeds use `brandIcon(ctx)` (the bot's avatar URL) for icons, and `COLORS.brand` is the crystal blue sampled from the logo.

**Live boards** (`src/discord/board.ts`): `syncBoard(ctx, channel, boardId, render)` keeps a set of Components V2 messages current in one channel (bot_meta `board:<boardId>:<channelId>` = ids and per-message fingerprints). `render(stamp)` is called with 0 for the fingerprint and with the time for the real message, so an "updated" line never counts as a change. Only changed messages are edited, plus the last one; a changed board waits `BOARD_MIN_EDIT_MS` (2 min) unless forced; an unchanged one is checked every 10 min. A deleted message (10008), or a different number of messages, means the whole board is posted again in order. Bump `version` when a layout changes. `removeNote` deletes the plain message that used to ping a role under a board (bot_meta `note:<channelId>`, `noteKey`): boards ping nobody since 2026-11-11, and `syncFeeds` calls it every round so a note from before goes away. V2 messages can't carry `content` or embeds, and an embed message can't be edited into one. `test/board.test.ts`.

**Trackers** (`src/trackers.ts`; kinds reward, fissure, cycle, baro, incarnon (`/track incarnon weapon:` with wiki autocomplete, or a dropdown of the weapons when it is left empty: a trackable from the Steel Path Circuit `hard` choices of `duviriCycle`, keyed `incarnon:<names>` so one DM goes out per week the weapon is up, matched by a name substring), arbitration (optional mission type and `minTier`), sortie (optional mission), archon, notable (an alert or invasion whose reward passes `isNotableReward`), price, weekly, clanEvent, squad (optional activity), riven (`/riven watch`, checked by rivens/watch.ts) and crack ("crack now", `minPlat` and `quietHours`, sent by crack.ts); the last six are never matched by `matchTracker`, each has its own sender; `/track …`, the boards' menus and the `notify:` buttons): `collectTrackables(ws, now, { arbitrations })` turns the world state and the schedule's hours into keyed items (invasions, alerts, Darvo, events, Steel Path, Varzia, Baro, fissures, cycle phases, an Arbitration from `ARBITRATION_LEAD_MS` before it starts) and `matchTracker(spec, item)` is pure; a reward keyword is a case-insensitive substring. Varzia's raw item names go through `resurgenceItemName` (worldstate.ts: "T1 Void Projection Nidus Saryn Vault A Bronze" → "Lith relic · Nidus Saryn A", "M P V Prime Strun Weapon" → "Strun Prime"), shared by the board, `/wf resurgence`, the status page and MCP, so `/track reward Strun Prime` matches; the feed's `ducats` are Regal Aya and its `credits` Aya. The notifier de-duplicates per tracker with `seen_worldstate` keys `track:<id>:<item key>` and sends one DM per member per round. Each item carries its `source` (arbitration, alert, fissure, cycle, …), which picks its icon in the DM. **DMs** (`src/discord/dm.ts`, `test/dm.test.ts`) are Components V2 cards in the boards' look: `trackerDm` (one block per tracker, an icon per item, at most 6 rewards per item, when it ends), `priceDm` (a link button to warframe.market), `rivenDm`, `clanEventDm` and `squadDm` (a link button to the post), `noticeDm` (a heading and a few lines) and the weekly card, all sent by `sendDm`, which logs a closed DM and returns false instead of throwing. A DM carries only link buttons: a tap on anything else would not reach the guild-only interaction handler.

**Notifications are DMs, never role pings** (`subscriptions.ts`, `ping-roles.ts`, `staff.ts`, `test/subscriptions.test.ts`; the owner's decision of 2026-11-11, "DM based subscription only": do not bring role pings back without asking): Ordis pings no role on his own. Whoever wants to hear about something has a tracker and gets a DM. `subscribe`/`unsubscribe` add and remove one by its spec (`sameSpec` compares by meaning; `MAX_TRACKERS_PER_USER` is 15, which only `force` skips). The plain on/off ones are buttons `notify:<key>` (`TOGGLES` in feeds/controls.ts: `weekly`, `clanEvent`, `squad`; `handleNotifyButton`, an ephemeral answer): all three sit on the roles panel, the weekly one also under the weekly post and on the sortie board. A clan event and a squad are announced the moment they are posted, not by the notifier: `notifyClanEvent` (called by `createClanEvent`, skips whoever created it) and `notifySquad` (called by `createSquad` in `src/lfg/squads.ts`, skips the host; a `squad` tracker with an `activity` only hears about that one, compared without case). `convertPingRoles` (ClientReady) was the one-time move: migration 38 dropped the six role settings and the activities' ping role and left the role IDs in bot_meta `legacy_ping_roles:<guild>`; every holder of an old ping role (Alerts, Arbitrations, Baro Ki'Teer, Weeklies, Clan Events, Squad Finder) got the tracker that says the same (`ROLE_SUBSCRIPTIONS`, past the limit on purpose), the roles left the self-assign menu, each member moved was told in a DM and the staff got a summary; nothing is marked done until the member list could be read, and bot_meta `ping_roles_converted` (`pingRoleConversion`) keeps what it did. It does not delete the roles. `staffNotice` (`staff.ts`) is Ordis's note to the staff about the bot itself: the status channel, else the moderation log, never throws. The only role ping left is one staff asks for by hand (`postAnnouncement`'s `pingRoleId`, MCP `send_announcement` `ping_role_id`).

**A deleted channel or role** (`broken-settings.ts`, `test/broken-settings.test.ts`): a setting that points at a channel or category that no longer exists made its feature fail without a word. `SETTING_USES` is the one list of every setting that holds a channel or a category, what it is for and the `/setup` command that sets it (a test compares it with `getSettings`, so a new channel setting needs a line there). On `ChannelDelete` (`reportDeletedChannel`) and once at every start (`checkSettings`: an ID that is not in the cache is fetched, and only Discord's "Unknown Channel", 10003, counts as gone, never a missing permission or a failed request) the settings that pointed at it are cleared, remembered in bot_meta `settings_lost` (`lostSettings` drops an entry once its setting has a value again) and told to the staff with `staffNotice`. `reportDeletedRole` (`GuildRoleDelete`) takes a deleted role out of the self-assign menu and redraws the roles panel, and says so when it was a Level or a mastery role. The panel's Overview shows the lost settings as a warning and `get_bot_health.lostSettings` lists them.

**Emojis** (`src/discord/emoji.ts`, `src/discord/app-emojis.ts`): code asks for a logical name (`e('arbitration')` in text, `emojiFor()` for buttons and select options, `factionEmoji`, `tierEmoji`, `shardEmoji`, `rewardEmoji`); `EMOJI` maps each to custom emoji names and a Unicode stand-in, so a missing emoji makes a message plainer, never broken. The registry is the clan server's emojis (the Warframe icons staff uploaded: `Arbitration`, `Sortie`, `T1Fissure`…`T4Fissure`, `OrokinDucats`, `platinum`, the `tau*` archon shards, …; they win on a name clash) plus Ordis's application emojis `wf_*` (factions, the riven icon and the Madurai/Vazarin/Naramon polarities, Baro, Darvo, Teshin, Varzia, Forma, Catalyst, …), which the `emojis` job uploads from the wiki's icons or, where the wiki has none, draws itself (`APP_EMOJIS`: a wiki file name or a drawing function; a failed one is retried a day later) and reloads every 30 min. `src/imaging/badges.ts` draws those with pureimage at 4x and averages down to 128 px (pureimage only smooths horizontally, and its bitmaps start opaque black, hence `blank()`): the Arbitration tier badges `wf_tier_s`…`wf_tier_f` in the Arbitration board's `TIER_COLOR`, `wf_omnia` (white line art like the clan's fissure icons, Ω from the Greek Roboto subset, `FONT_GREEK_BOLD`) and `wf_cycle` (sun and moon halves); `test/badges.test.ts`. `src/imaging/icons.ts` draws the states of the open worlds (`wf_day`, `wf_night`, `wf_warm`, `wf_cold`, `wf_fass`, `wf_vome`; `cycleEmoji(state)`, used by the cycles board, the DMs and the status page), Duviri's five moods as faces (`wf_joy`…`wf_fear`) and two markers (`wf_star` for a reward worth a detour, `wf_bolt` for a quick fissure). The wiki supplies the resources invasions and alerts pay (`wf_orokin_cell`, `wf_neurodes`, `wf_fieldron`… matched by `rewardEmoji`; they have no Unicode stand-in, so a missing icon just leaves a plain reward line), `wf_relic` and `wf_duviri`. Custom emojis render in message text, V2 text displays, embed descriptions and field values, not in embed titles, authors or footers. `get_bot_health.emojis` lists the names that fall back. `test/emoji.test.ts`.

**Look and feel** (`style.ts`; the web half is in `src/web/CLAUDE.md`): `style.ts` has `COLORS`, one `ICON` per kind of information (`heading(icon, text)` titles an embed, so "Void fissures" looks the same in a command and in a chat answer) and `footer(source)`, the footer every public embed ends with: where the data came from, then the bot's name and avatar (`syncIdentity` sets the brand when the bot is ready or renamed). Fissures are grouped by relic tier, soonest to end first.

**Editing the bot's messages** (`src/discord/messages.ts`): `editOwnMessage` / `ownMessages` are the one implementation behind the MCP tool `edit_message` (channel_id, message_id, content; find the id with `read_messages`, `bot: true`) and the admin panel's **Messages** page (`src/web/admin/messages-page.ts`, under Server: pick a channel, edit the text of each message Ordis wrote there, audit-logged, returns to the same channel). Discord only lets a bot edit its own messages, so anyone else's are refused (and not offered in the panel); embeds are kept, text is limited to 2000 characters, mentions never ping. `edit_message` can also turn a message into an embed in the panels' look (`embed`: title, description, fields, `logo` = the clan logo as thumbnail, footer; `cardEmbed` checks Discord's 6000-character total, `editOwnMessageCard` replaces the old text, `content` becomes an optional line above): the welcome guide and the rules are such embeds. The panel's Messages page still edits only the text above an embed. `test/messages.test.ts` and a panel test in `test/admin.test.ts`.

**Event end times** (`events.ends_at`/`ended`, migration 25): an event may have an optional end. `/event create ends:`, the panel's Events form (UTC datetime) and the MCP `create_event` `ends_at` take a length after the start ("2h", `parseEnd` in `time.ts`) or a time; it must be after the start and at most 30 days later (`createClanEvent`). `renderEvent`/`whenText`/`isOver` show "Ends ...", "Happening now" while it runs and "ENDED" (no RSVP buttons) afterwards; an event with no end keeps the old rule (buttons vanish an hour after the start). `upcomingEvents` also returns events that are still running, and the notifier's `finishEvents` (same tick as the reminders) re-renders the post once when the end passes (`eventsDueToEnd`/`markEventEnded`). `test/event-end.test.ts`. `createClanEvent` also creates a **native Discord scheduled event** (External, location "In game", end = the event's end or start + 2 h, description links our post; id in `events.discord_event_id`, deleted on cancel; a failure only logs, our post with its RSVP buttons stays the main one) and DMs the members who asked for new clan events (`notifyClanEvent`, tracker kind `clanEvent`); nobody is pinged in the channel. An event whose post fails is deleted again (`deleteEvent`), so nothing sits in the list that nobody can see.

**Repeating events** (`event-repeat.ts`, migration 39: `events.repeat_days`/`series_id`/`next_id`; `test/event-repeat.test.ts`): `/event create repeat:`, the panel's Events form and MCP `create_event` `repeat` take every day, week, 2 weeks or 4 weeks (`REPEAT_DAYS`, whole days only, so no calendar rule is needed; the event must be shorter than its rhythm). The `events` job (`repeatEvents`, after the reminders and `finishEvents`) posts the next round once the current one is over (`eventsDueToRepeat`: past its end, or an hour past its start): a new event of its own through `createClanEvent` (same title, description, length, creator and channel; fresh RSVPs, its own reminder, Discord event and `clanEvent` DMs), linked from the round before (`next_id`, set in the same transaction as the insert, so a round is never posted twice). `nextOccurrence` counts from the series' first start (`series_id`) in whole intervals at the same time of day in `CLAN_TIMEZONE` (`addDaysInZone` in `time.ts`; Config page, default UTC), so a weekly 20:00 stays 20:00 through a clock change and one odd round shifts nothing; rounds missed while Ordis was off are skipped. A cancelled round is followed like any other (`/event cancel` is one evening off); a series ends with `/event cancel series:True` (`cancelClanEvent` `stopSeries`), `/event repeat every:Never`, the panel's "Stop repeating" or MCP `set_event_repeat`/`cancel_event stop_series`, all of which act on the newest round (`newestRound`), the one that carries the series on. When the series' channel is gone the announcements channel takes over; when nothing can be posted the staff are told once (`staffNotice`) and it is tried again every 15 minutes.

**Vault watch** (`vault-watch.ts`, the hourly `vault-watch` job, `test/vault-watch.test.ts`): a post in the game news channel when prime sets and their relics leave the drop tables, come back, or are new. `snapshotOf(book)` reads name → vaulted for every relic and every set that some relic holds (the relic book's `sets`, built from WFInfo's `eqmt` table; no request of its own), `vaultChanges` compares it with the last record (bot_meta `vault_watch`, written only when something changed) and `vaultEmbed` writes the post (sets first, relics by tier with `relicList`). The first look only records. A stale book, a table with fewer than 100 relics or one that lost a fifth of its relics is left alone; more than 120 relics changing at once is taken as the new record without a post; a change already announced (`seen_worldstate` keys `vault:<set|relic>:<v|o|n>:<name>`, kept 30 days) is not announced again, so a flag that flips back and forth says each thing once. The record is written after the post went out, so a channel that cannot be posted in today gets the news later; without a news channel it is kept without a post. Either way the members who collect one of the sets are told in a DM (`notifyWishlistVault`, `src/wishlist/`). `get_bot_health.vaultWatch`.

When a new post goes out, `markOutdatedWeeklies` greys out the earlier ones in the channel (`outdatedCard` for a Components V2 card and `outdatedEmbeds` for the older embed posts: grey `COLORS.muted`, buttons removed, an "Outdated" note on top; it reads the last 50 messages; `greyOldWeeklies` runs it once at every start and keeps the newest post; a failure is only logged; `test/weekly-outdated.test.ts`). - **Promo codes** (`src/discord/promo-codes.ts`, `/setup promos`, setting `promoChannelId`, migration 33, MCP `update_bot_settings promo_channel_id`): one live message (`postLive`/`editLive`, bot_meta `promo_panel`) with the codes under Active Codes on the wiki's "Promo Codes" page, read from the page's raw wikitext (`readWikiSource` in `src/warframe/wiki.ts`, one cached request; `promoTextFromSource` turns each `<br>` into ", " before `cleanWikitext`, because the wiki puts several rewards, or codes, in one cell with `<br>` between them and the index's cleaner makes that a plain space), else from the local wiki index, and refreshed once a UTC day by the notifier (`updatePromoCodes`; a new channel gets the list within a minute). `parseActiveCodes` is pure: rows are cells joined with " · ", empty cells are dropped, so it finds the date cell by pattern, takes what follows as the rewards (comma-joined; a cell's stray leading or trailing comma is dropped, a code cell is split on spaces and commas) and leaves out codes past their own end date (they vanish from the list even while the wiki still shows them as active). Each code also keeps its rewards as `items` (the reward cells split on ", ", a leading "Adds" dropped). Layout (`promoPanel`): an intro line, then each dated code as `**[CODE](warframe.com/promocode?code=…)** · <summary>` with `-# 📅 <t:added:D> · <expiry>` below it (`datesLine`, `expiryText`: `ends <t:…:D> (<t:…:R>)`, "no end date" for Indefinite, or "expiry unknown") and a blank line between codes, newest added first (`datePromoCodes`); the codes with no known added date follow under a bold "Older codes" heading, one line each in the wiki's order, with " · ends <t:…:D>" only when the end is known. The heading is written only together with the first line under it that fits. `summarizeRewards` (pure, fixed rules, no model): one item is its name; several are counted by kind (the name's ending: display incl. "Display Frame" and "Fusion Display", glyph, decoration, sigil, emblem, booster, skin, syandana, ephemera, poster, scene) in the order the kinds first appear, "N plural" above one, the theme (the words every name shares, kind words left out) before the first kind, joined with ", " and " and " ("4 Movember displays", "Pride glyph and 2 displays", "3 Mistletoe Community glyphs"); any item of an unknown kind gives all the names joined with ", ". Cut to 200 characters. The added date is the row's start day (`parseDates`, `dayToMs`: a day is noon UTC and an impossible day counts as unknown), else when Ordis first read the code: table `promo_codes_seen` (migration 42, `Store.promoFirstSeen`), whose very first read stores NULL for every code, since those were already there. Bump `PANEL_VERSION` (now 5) when the layout changes, so the live message is redrawn at once. Only whole entries fit in the 4000-character description. No codes read means the message stays as it is and the next try is an hour later. An edit gives members no unread marker, so a new code is only seen by looking.
- **Game news** (`src/discord/news.ts`, `/setup news`, setting `newsChannelId`, migration 34, MCP `update_bot_settings news_channel_id`): the notifier (`postNews`, every minute) posts each new item once as an embed (tag, title linking to the post, timestamp; the in-game ones with their picture). Two sources: the world state's `news` (what the in-game news panel shows, so updates, hotfixes, Prime Access and Devstreams, no request of its own; mobile-only posts skipped) and Warframe's official Steam announcements (`ISteamNews/GetNewsForApp`, app 230410, only the `steam_community_announcements` feed, asked at most every 30 min through the shared `ApiClient`; the BBCode is stripped by `steamText`). A Steam post with the same title as an in-game one is dropped (`withoutDuplicates`). De-duplicated with `seen_worldstate` keys `news:...`; nothing older than 7 days is announced; the first read of a source for a channel (bot_meta `news_seeded:<source>` = channel id) only records what exists, so a new channel is not flooded; at most 5 posts a round, the rest wait for the next minute. `test/news.test.ts`.

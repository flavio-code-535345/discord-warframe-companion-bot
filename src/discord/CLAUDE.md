# Discord layer

Notes for this folder. The rules that apply everywhere, the commands and the list of the other notes are in the root `CLAUDE.md`.

**Discord interactions** (`src/discord/bot.ts`): routes slash commands (`src/discord/commands/*`, each exporting a `Command`), autocomplete, and buttons (`src/discord/buttons.ts`). Commands are registered **guild-scoped** to `DISCORD_GUILD_ID` on every `ClientReady`; the bot deliberately serves only that one guild. Button custom IDs are `rsvp:<eventId>:<going|maybe|declined>`, `lfg:<postId>:<join|leave|close>`, `roles:<roleId>`, `giveaway:<id>:enter`, `notify:<weekly|clanEvent|squad>` (posts from before the rename carry `weekly:toggle`, routed to the same handler) and `feeds:<mine|plan>`, and the World State boards' menus are `feeds:track:<feed>`, `feeds:untrack`, `feeds:plan` and `feeds:bounty` (`handleFeedSelect`), so they keep working after restarts.

**Notifier** (`src/discord/notifier.ts`, the `world-state` and `events` jobs): every minute `worldStateJob` reads the world state (fetched at most every `WORLDSTATE_POLL_SECONDS`) and the Arbitration schedule (`loadArbitrations`), builds one `FeedInput` (`feedInput`) and hands it to `syncFeeds` (the World State boards, `feeds/CLAUDE.md`), then DMs what matches the members' trackers and makes the weekly reset post. The Arbitration board and the Arbitration DMs work from the schedule alone, so they keep going while the world state is off or failing; a failed world state read is rethrown at the end, so the job's health shows it. The `events` job sends event reminders 15 minutes before start and re-renders ended events.

**Identity:** `src/discord/identity.ts` syncs the bot's Discord username (`BOT_NAME`) and avatar (`assets/clan-logo.png`, which the Dockerfile copies into the image) on every `ClientReady`. It only calls the API when something differs, because Discord rate-limits both; the avatar hash is kept in the `bot_meta` table. Embeds use `brandIcon(ctx)` (the bot's avatar URL) for icons, and `COLORS.brand` is the crystal blue sampled from the logo.

**Live boards** (`src/discord/board.ts`): `syncBoard(ctx, channel, boardId, render)` keeps a set of Components V2 messages current in one channel (bot_meta `board:<boardId>:<channelId>` = ids and per-message fingerprints). `render(stamp)` is called with 0 for the fingerprint and with the time for the real message, so an "updated" line never counts as a change. Only changed messages are edited, plus the last one; a changed board waits `BOARD_MIN_EDIT_MS` (2 min) unless forced; an unchanged one is checked every 10 min. A deleted message (10008), or a different number of messages, means the whole board is posted again in order. Bump `version` when a layout changes. `removeNote` deletes the plain message that used to ping a role under a board (bot_meta `note:<channelId>`, `noteKey`): boards ping nobody since 2026-11-11, and `syncFeeds` calls it every round so a note from before goes away. V2 messages can't carry `content` or embeds, and an embed message can't be edited into one. `test/board.test.ts`.

**Trackers** (`src/trackers.ts`; kinds reward, fissure, cycle, baro, arbitration (optional mission type and `minTier`), sortie (optional mission), archon, notable (an alert or invasion whose reward passes `isNotableReward`), price, weekly, clanEvent, squad (optional activity) and riven (`/riven watch`, checked by rivens/watch.ts); the last five are never matched by `matchTracker`, each has its own sender; `/track …`, the boards' menus and the `notify:` buttons): `collectTrackables(ws, now, { arbitrations })` turns the world state and the schedule's hours into keyed items (invasions, alerts, Darvo, events, Steel Path, Varzia, Baro, fissures, cycle phases, an Arbitration from `ARBITRATION_LEAD_MS` before it starts) and `matchTracker(spec, item)` is pure; a reward keyword is a case-insensitive substring. Varzia's raw item names go through `resurgenceItemName` (worldstate.ts: "T1 Void Projection Nidus Saryn Vault A Bronze" → "Lith relic · Nidus Saryn A", "M P V Prime Strun Weapon" → "Strun Prime"), shared by the board, `/wf resurgence`, the status page and MCP, so `/track reward Strun Prime` matches; the feed's `ducats` are Regal Aya and its `credits` Aya. The notifier de-duplicates per tracker with `seen_worldstate` keys `track:<id>:<item key>` and sends one DM per member per round. Each item carries its `source` (arbitration, alert, fissure, cycle, …), which picks its icon in the DM. **DMs** (`src/discord/dm.ts`, `test/dm.test.ts`) are Components V2 cards in the boards' look: `trackerDm` (one block per tracker, an icon per item, at most 6 rewards per item, when it ends), `priceDm` (a link button to warframe.market), `rivenDm`, `clanEventDm` and `squadDm` (a link button to the post), `noticeDm` (a heading and a few lines) and the weekly card, all sent by `sendDm`, which logs a closed DM and returns false instead of throwing. A DM carries only link buttons: a tap on anything else would not reach the guild-only interaction handler.

**Notifications are DMs, never role pings** (`subscriptions.ts`, `ping-roles.ts`, `staff.ts`, `test/subscriptions.test.ts`; the owner's decision of 2026-11-11, "DM based subscription only": do not bring role pings back without asking): Ordis pings no role on his own. Whoever wants to hear about something has a tracker and gets a DM. `subscribe`/`unsubscribe` add and remove one by its spec (`sameSpec` compares by meaning; `MAX_TRACKERS_PER_USER` is 15, which only `force` skips). The plain on/off ones are buttons `notify:<key>` (`TOGGLES` in feeds/controls.ts: `weekly`, `clanEvent`, `squad`; `handleNotifyButton`, an ephemeral answer): all three sit on the roles panel, the weekly one also under the weekly post and on the sortie board. A clan event and a squad are announced the moment they are posted, not by the notifier: `notifyClanEvent` (called by `createClanEvent`, skips whoever created it) and `notifySquad` (called by `createSquad` in `src/lfg/squads.ts`, skips the host; a `squad` tracker with an `activity` only hears about that one, compared without case). `convertPingRoles` (ClientReady) was the one-time move: migration 38 dropped the six role settings and the activities' ping role and left the role IDs in bot_meta `legacy_ping_roles:<guild>`; every holder of an old ping role (Alerts, Arbitrations, Baro Ki'Teer, Weeklies, Clan Events, Squad Finder) got the tracker that says the same (`ROLE_SUBSCRIPTIONS`, past the limit on purpose), the roles left the self-assign menu, each member moved was told in a DM and the staff got a summary; nothing is marked done until the member list could be read, and bot_meta `ping_roles_converted` (`pingRoleConversion`) keeps what it did. It does not delete the roles. `staffNotice` (`staff.ts`) is Ordis's note to the staff about the bot itself: the status channel, else the moderation log, never throws. The only role ping left is one staff asks for by hand (`postAnnouncement`'s `pingRoleId`, MCP `send_announcement` `ping_role_id`).

**A deleted channel or role** (`broken-settings.ts`, `test/broken-settings.test.ts`): a setting that points at a channel or category that no longer exists made its feature fail without a word. `SETTING_USES` is the one list of every setting that holds a channel or a category, what it is for and the `/setup` command that sets it (a test compares it with `getSettings`, so a new channel setting needs a line there). On `ChannelDelete` (`reportDeletedChannel`) and once at every start (`checkSettings`: an ID that is not in the cache is fetched, and only Discord's "Unknown Channel", 10003, counts as gone, never a missing permission or a failed request) the settings that pointed at it are cleared, remembered in bot_meta `settings_lost` (`lostSettings` drops an entry once its setting has a value again) and told to the staff with `staffNotice`. `reportDeletedRole` (`GuildRoleDelete`) takes a deleted role out of the self-assign menu and redraws the roles panel, and says so when it was a Level or a mastery role. The panel's Overview shows the lost settings as a warning and `get_bot_health.lostSettings` lists them.

**Emojis** (`src/discord/emoji.ts`, `src/discord/app-emojis.ts`): code asks for a logical name (`e('arbitration')` in text, `emojiFor()` for buttons and select options, `factionEmoji`, `tierEmoji`, `shardEmoji`, `rewardEmoji`); `EMOJI` maps each to custom emoji names and a Unicode stand-in, so a missing emoji makes a message plainer, never broken. The registry is the clan server's emojis (the Warframe icons staff uploaded: `Arbitration`, `Sortie`, `T1Fissure`…`T4Fissure`, `OrokinDucats`, `platinum`, the `tau*` archon shards, …; they win on a name clash) plus Ordis's application emojis `wf_*` (factions, the riven icon and the Madurai/Vazarin/Naramon polarities, Baro, Darvo, Teshin, Varzia, Forma, Catalyst, …), which the `emojis` job uploads from the wiki's icons or, where the wiki has none, draws itself (`APP_EMOJIS`: a wiki file name or a drawing function; a failed one is retried a day later) and reloads every 30 min. `src/imaging/badges.ts` draws those with pureimage at 4x and averages down to 128 px (pureimage only smooths horizontally, and its bitmaps start opaque black, hence `blank()`): the Arbitration tier badges `wf_tier_s`…`wf_tier_f` in the Arbitration board's `TIER_COLOR`, `wf_omnia` (white line art like the clan's fissure icons, Ω from the Greek Roboto subset, `FONT_GREEK_BOLD`) and `wf_cycle` (sun and moon halves); `test/badges.test.ts`. `src/imaging/icons.ts` draws the states of the open worlds (`wf_day`, `wf_night`, `wf_warm`, `wf_cold`, `wf_fass`, `wf_vome`; `cycleEmoji(state)`, used by the cycles board, the DMs and the status page), Duviri's five moods as faces (`wf_joy`…`wf_fear`) and two markers (`wf_star` for a reward worth a detour, `wf_bolt` for a quick fissure). The wiki supplies the resources invasions and alerts pay (`wf_orokin_cell`, `wf_neurodes`, `wf_fieldron`… matched by `rewardEmoji`; they have no Unicode stand-in, so a missing icon just leaves a plain reward line), `wf_relic` and `wf_duviri`. Custom emojis render in message text, V2 text displays, embed descriptions and field values, not in embed titles, authors or footers. `get_bot_health.emojis` lists the names that fall back. `test/emoji.test.ts`.

**Look and feel** (`style.ts`; the web half is in `src/web/CLAUDE.md`): `style.ts` has `COLORS`, one `ICON` per kind of information (`heading(icon, text)` titles an embed, so "Void fissures" looks the same in a command and in a chat answer) and `footer(source)`, the footer every public embed ends with: where the data came from, then the bot's name and avatar (`syncIdentity` sets the brand when the bot is ready or renamed). Fissures are grouped by relic tier, soonest to end first.

**Editing the bot's messages** (`src/discord/messages.ts`): `editOwnMessage` / `ownMessages` are the one implementation behind the MCP tool `edit_message` (channel_id, message_id, content; find the id with `read_messages`, `bot: true`) and the admin panel's **Messages** page (`src/web/admin/messages-page.ts`, under Server: pick a channel, edit the text of each message Ordis wrote there, audit-logged, returns to the same channel). Discord only lets a bot edit its own messages, so anyone else's are refused (and not offered in the panel); embeds are kept, text is limited to 2000 characters, mentions never ping. `edit_message` can also turn a message into an embed in the panels' look (`embed`: title, description, fields, `logo` = the clan logo as thumbnail, footer; `cardEmbed` checks Discord's 6000-character total, `editOwnMessageCard` replaces the old text, `content` becomes an optional line above): the welcome guide and the rules are such embeds. The panel's Messages page still edits only the text above an embed. `test/messages.test.ts` and a panel test in `test/admin.test.ts`.

**Event end times** (`events.ends_at`/`ended`, migration 25): an event may have an optional end. `/event create ends:`, the panel's Events form (UTC datetime) and the MCP `create_event` `ends_at` take a length after the start ("2h", `parseEnd` in `time.ts`) or a time; it must be after the start and at most 30 days later (`createClanEvent`). `renderEvent`/`whenText`/`isOver` show "Ends ...", "Happening now" while it runs and "ENDED" (no RSVP buttons) afterwards; an event with no end keeps the old rule (buttons vanish an hour after the start). `upcomingEvents` also returns events that are still running, and the notifier's `finishEvents` (same tick as the reminders) re-renders the post once when the end passes (`eventsDueToEnd`/`markEventEnded`). `test/event-end.test.ts`. `createClanEvent` also creates a **native Discord scheduled event** (External, location "In game", end = the event's end or start + 2 h, description links our post; id in `events.discord_event_id`, deleted on cancel; a failure only logs, our post with its RSVP buttons stays the main one) and DMs the members who asked for new clan events (`notifyClanEvent`, tracker kind `clanEvent`); nobody is pinged in the channel.

**Community features** (migration 30; `test/community.test.ts`; the dojo research board and the starboard that came with them were removed again the same day at the owner's request, migration 31 drops their tables and settings: do not bring them back without asking). Settings: `birthdayChannelId` (`/setup birthdays`), `weeklyChannelId` (`/setup weekly`); both also in MCP `update_bot_settings` and `/setup off`. The features of that migration with a folder of their own have their notes there (`src/selfroles/`, `src/activity/`, `src/giveaways/`, `src/birthdays/`); the ones that live in this folder follow.
- **Price alerts** (`/track price item: below:`, `TrackerSpec` kind `price`, `src/discord/price-alerts.ts`): every 30 min (notifier tick, `PRICE_CHECK_MS`) one `priceCheck` per tracked item (max 30 items a round, stale cached prices are ignored); `priceDecision` alerts once at or below the limit and re-arms only after the price went back above it (bot_meta `price_alert:<trackerId>`). `matchTracker` never matches a price tracker (no trackable has that kind).
- **Weekly reset post** (`src/discord/weekly.ts`): after the Monday 00:00 UTC reset, once the world state shows the new Archon Hunt (or 6 h later anyway), one Components V2 card (`weeklyCard`) with the Circuit offers, the weekly Nightwave challenges, the Archon Hunt and Teshin's honors (the last two are the sortie board's `archonPart`/`honorsPart`); bot_meta `weekly_posted` = the week posted. Setting the channel calls `skipCurrentWeek`, so the first post is the next Monday. It is also DM'd (`sendWeekly`, `weeklySubscribers`) to every member with a `weekly` tracker (`/track weekly` or the button; never matched by `matchTracker`), each once; with no channel set the DMs still go out. MCP `send_weekly_now` sends this week's post at once (a new channel, a test). A "Weeklies by DM" button (`notifyButton('weekly')` in feeds/controls.ts, `notify:weekly`, `handleNotifyButton` in subscriptions.ts) under the channel post, on the sortie board and on the roles panel turns that tracker on or off; DMs carry no button, since a tap there would not reach the guild-only interaction handler.
- **Promo codes** (`src/discord/promo-codes.ts`, `/setup promos`, setting `promoChannelId`, migration 33, MCP `update_bot_settings promo_channel_id`): one live message (`postLive`/`editLive`, bot_meta `promo_panel`) with the codes under Active Codes on the wiki's "Promo Codes" page, read from the local wiki index and refreshed once a UTC day by the notifier (`updatePromoCodes`; a new channel gets the list within a minute). `parseActiveCodes` is pure: rows are cells joined with " · ", empty cells are dropped, so it finds the date cell by pattern, takes what follows as the rewards and leaves out codes past their own end date. No codes read means the message stays as it is and the next try is an hour later. An edit gives members no unread marker, so a new code is only seen by looking.
- **Game news** (`src/discord/news.ts`, `/setup news`, setting `newsChannelId`, migration 34, MCP `update_bot_settings news_channel_id`): the notifier (`postNews`, every minute) posts each new item once as an embed (tag, title linking to the post, timestamp; the in-game ones with their picture). Two sources: the world state's `news` (what the in-game news panel shows, so updates, hotfixes, Prime Access and Devstreams, no request of its own; mobile-only posts skipped) and Warframe's official Steam announcements (`ISteamNews/GetNewsForApp`, app 230410, only the `steam_community_announcements` feed, asked at most every 30 min through the shared `ApiClient`; the BBCode is stripped by `steamText`). A Steam post with the same title as an in-game one is dropped (`withoutDuplicates`). De-duplicated with `seen_worldstate` keys `news:...`; nothing older than 7 days is announced; the first read of a source for a channel (bot_meta `news_seeded:<source>` = channel id) only records what exists, so a new channel is not flooded; at most 5 posts a round, the rest wait for the next minute. `test/news.test.ts`.
